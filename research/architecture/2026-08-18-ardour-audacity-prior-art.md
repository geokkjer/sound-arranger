# Prior art: what 20 years of Audacity & Ardour tell the sound-arranger media engine

> **Date:** 2026-08-18. **Scope:** targeted design-doc pass (no C++ implementation read — both projects are GPL-2.0-or-later, compatible with our GPL-3.0-or-later, so nothing here is a legal clean room; the point is *design independence*, absorbing proven decisions without monolith-isms). **Sources:** full findings reports — [Audacity](2026-08-18-audacity-design-knowledge.md) (CMJ 2002 paper, AOSA chapter, archived wiki, PR/issue rationale, dev-mail) and [Ardour](2026-08-18-ardour-design-knowledge.md) (ardour.org manual, ardour-dev/LAD archives, author interviews). **Why:** our Phase-1 questions — media pool format, waveform peaks, edit-during-playback, click-free transport, undo gestures, overlapping clips, PDC — are exactly where 20 years of shipped DAW experience is cheap insurance against reinventing the wheel with worse results. The minimal core's big lessons (PDC from day one, disk streaming rings, sample-accurate scheduling, region = path+range) were already inherited and validated by Spikes A–B; this pass checks what we have *not* designed yet.

## 1. Audacity — the block-store editor (summary; see the full report)

Audio = a sequence of refcounted disk blocks (k..2k-sample invariant; ~1 MB blocks shipped; `.aup3` = sqlite `SampleBlock` single file). Peaks = min/max per 256-sample reduction stored per block, per-pixel pyramid on demand, background computation with striped placeholders. Playback = 3 ad-hoc threads with shared variables (AOSA admits it), `PlaybackSchedule` split from the device thread; a documented release-ordering bug (issue #2098); destructive edits disabled during playback. Undo = structural snapshots (node list) over refcounted blocks — constant time, ~64–128 KB per op, gesture grouping via history "summary". Debt: block files exposed to users (fixed by aup3), TrackPanel "truly horrible", `GetLink` mono/stereo special-casing (~100 call sites), 16-bit quantization accumulation.

## 2. Ardour — the realtime workstation (summary; see the full report)

Source = file reference, Region = offset+length into it, cheap, never equivalent to files; splitting/trimming never touches files. Regions stack in **layers** with arbitrary overlaps; a crossfade is not an entity between two regions — **each region carries its own end crossfades**, bottom-most rendered first, each on top crossfading down onto those beneath. Per-region gain and a per-region gain-envelope automation curve travel with the region. The audio thread **never reads regions** — it pulls from per-track ring buffers filled by the **butler thread** (kernel read-ahead is trusted; read-ahead default 5 s; writes batched in 256 kB; LRU fd cache). **PDC was retrofitted in 2005** (two alignment styles, loopback test protocol, "the phase of the moon" failure surface) and was **still incomplete in 2018** ("full latency compensation, everywhere, for everything" as an Ardour 6.0 goal); Ardour uses the **read-ahead** strategy (the clock shows heard audio, not where files are read). Every region has short default fades "to de-click the transitions"; envelopes interpolate continuously. A Session is a **folder** (main snapshot + named snapshots + `.history` persisted undo + `interchange/` raw audio + `peaks/`); undo scope is deliberately split (pianoroll history ephemeral); snapshots = named frozen versions with "keep working vs switch" semantics. Clock (speed) is separated from time (position); the **TempoMap** has constant/ramped markers, **audio-locked vs music-locked** markers; **nutempo/superclock**: never convert musical↔audio time "except when we absolutely have to, and to never convert back"; durations need an associated position. Debt: PDC gaps, time-conversion errors, 256 kB legacy write chunks, session-format churn — and Paul Davis's honest "please don't start a new project" (a greenfield DAW is measured in years).

## 3. Mapping to sound-arranger: our open questions → their experience → disposition

| Our Phase-1 question | What they say | Disposition for us |
|---|---|---|
| **Media pool format** | Audacity's block store exists to make *destructive* edits cheap; their main regret is raw block files exposed to users → single-file `.aup3` with GC/compaction; the paper recommends **32-bit float on disk**. Ardour: sources are whole files (immutable), regions reference ranges; session = folder with `interchange/` (raw audio), `peaks/`, `dead sounds/`. | We are **non-destructive** (ACID model: clips reference ranges into immutable sources; the composition is a log), so no block store needed — our `ClipRef { path, start, len }` + content-hash-referenced sources (minimal-core note) is the shape they both moved toward. Adopt: pool sources as **32-bit float WAV** (16-bit only at bounce/export); opaque managed pool, never exposed as raw files; the session container follows Ardour's folder shape (main log + named snapshots + media pool + peaks + history). |
| **Waveform peaks** | Audacity: min/max per 256-sample group ("reductions"), per-pixel pyramid over reductions when zoomed out, raw samples when zoomed in; on-demand background computation with striped placeholders; Min/Max/RMS cache. Ardour: `.peak` sidecars. | **Adopt the pyramid**: base bin = 256 samples, levels ×2, min/max per bin; background-computed; persisted per-source peak sidecar. This is the concrete answer to Phase 1's "live waveform peaks" — proven, no need to design it. |
| **Edit-during-playback** | Audacity *disabled* destructive edits while playing; #2098 (TimeQueue relies on RingBuffer release-ordering; RepositionPlayback runs after Put) is a scheduling-discipline warning. Ardour: the audio thread never reads regions — it pulls from butler-filled rings, so playlist edits are decoupled from the process cycle and take effect at the next refill. | Our architecture is already Ardour's: the engine render loop pulls from SPSC rings; the profile edits the log, applied at their frame (Spike A invariant) — no need to disable edits. Phase-1 requirement: the clip-editor schedules cuts at a frame with crossfade (Spike B's mechanism); never stop the stream to edit. |
| **Overlapping clips (layering)** | Ardour: regions stack in layers with arbitrary overlaps; **each region carries its own end crossfades**, bottom-up render. A crossfade is a per-region property, not a between-regions entity. | The generalization of our sequential splice. Phase-1: the clip stack renders bottom-up; per-clip end fades; the mixer node is the natural home. Our Spike B crossfade is the seed of the per-region end fade. |
| **Click-free transport/edits** | Ardour: every region has short default fades explicitly "to de-click the transitions"; envelopes interpolate continuously (never stepped). | Phase-1 defaults: short equal-power fades on every clip edge + transport start/stop ramps — the Spike B mechanism, applied as the default, not an afterthought. |
| **Undo / gesture grouping** | Audacity: structural snapshots + refcounted blocks; history "summary" groups a gesture into one undo step. Ardour: undo persisted to `.history` (survives restart), separate scopes (pianoroll ephemeral), snapshots = named frozen versions ("keep working vs switch"). | Our event-sourced log is structurally ahead (undo = truncate + replay, byte-identical; fork = snapshot). Adopt their *semantics*: gesture coalescing (one gesture = one undo step — already in the minimal-core note's log rules), persisted history, scoped undo per view, named log forks as snapshots. |
| **Thread model / scheduler** | Audacity: 3 ad-hoc threads + shared variables, no mutexes (AOSA admits the mess); `PlaybackSchedule` split from the device thread (PR #812). Ardour: butler thread fills rings; **transport position is implied by pull order**; buffers reset and refilled before the audio thread advances; trust kernel read-ahead; keep files open (LRU fd cache); writes batched in 256 kB; read-ahead default 5 s. | Validates our discipline (one render path, media threads behind SPSC rings, time owned by the core clock, `devices.rs` a thin seam). Spike B notes to carry: read-ahead is a user-set tunable (our 1.37 s default is small vs their 5 s — fine for the spike, revisit for the pool); write batching can be larger than our 1024-sample chunks (flush-per-chunk was for crash safety; batch + flush is the Phase-1 shape). |
| **PDC** | Ardour retrofitted PDC in 2005 and it was **still incomplete in 2018** — the canonical retrofit horror story. Read-ahead vs write-behind: Ardour reads ahead so the clock shows heard audio; our interpreter delays faster paths (output delayed by max latency). Monitoring: software monitoring adds round-trip latency (1.5–2 ms A/D/A); USB/FireWire latency varies. | The strongest validation of PDC-from-day-one (Spike A). Phase-1 note: consider read-ahead compensation (clock = heard audio) for live monitoring; record the failure surface (alignment styles, capture-time vs existing-material) so we don't rediscover it. |
| **Tempo map** | Ardour: constant/ramped markers, audio-locked vs music-locked; **superclock**: never convert musical↔audio time repeatedly; durations need an associated position; storing time as superclock makes sample-rate changes trivial. | Our absolute-frame clock IS the superclock analog (events carry `at_frame`; beats derived via the tempo map) — validated. Extensions to track: ramped tempo markers; music-locked objects (we're audio-locked by default — log stores frames); the "durations need a position" rule already holds in our event model. |

## 4. Debt evidence — validating the minimal-core choice

Both projects' *own* postmortems are the strongest argument for our direction: Audacity's "retroactive plug-in development — discovering the interfaces that allow us to *subtract* existing features" (48 modules, ~38 "Extract lib" PRs), the `GetLink` mono/stereo special-casing, the three thread models, the GUI-coupled TrackPanel; Ardour's PDC retrofit that never finished, its time-conversion debt, and its legacy buffering choices. We draw seams before code exists (composition-seams note) — the research confirms it with two projects' paid-in-full experience of the alternative. The honest counterweight is Paul Davis's "please don't start a new project" — a greenfield full DAW is measured in years; our mitigation is the minimal core + plugin budget rule (umbrella-first note): we are building a small platform and one profile, not a full DAW.

## 5. Decision candidates (for Agent Notes when Phase 1 starts)

- **Media pool: immutable 32-bit-float WAV sources, content-hash referenced, opaque managed pool** — confirmed by both projects (Audacity's float-on-disk + don't-expose-files lessons; Ardour's immutable-source shape).
- **Waveform peaks: 256-sample min/max reduction pyramid, background-computed, persisted sidecar** — adopt Audacity's proven structure.
- **Edit-during-playback: never stop the stream; schedule cuts at a frame with crossfade** — Spike B's mechanism is the enabler.
- **Layered clip stack with per-clip end fades (Ardour's model)** — the generalization of sequential splices; the mixer owns it.
- **Click-free defaults: short equal-power fades on clip edges and transport** — from Ardour's de-click discipline.
- **Gesture coalescing: one user gesture = one logged gesture** — explicit in the log rules.
- **PDC read-ahead for monitoring (clock = heard audio)** — Phase-1 mixer/PDC refinement; record Ardour's failure surface first.
