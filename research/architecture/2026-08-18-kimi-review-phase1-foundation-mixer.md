# Second opinion — kimi-cli review of the Phase-1 foundation + soft mixer

> **Source:** `kimi-cli` non-interactive review, 2026-08-18 (kimi session `session_9222ac75-6332-4a21-accc-65d955e991cb`).
> **Reviewed:** the [Phase-1 note](../../.agents/notes/proposed/architecture/2026-08-18-phase-1-sound-arranger-profile.md), the per-port audio fan-in in `crates/engine/src/graph.rs`, the logged `SetParam` in `log.rs`/`render.rs`, the new `plugins/mixer.rs`, the tone's bus-claim removal, and the Phase-1 acceptance tests.
> **Verdict:** no criticals — the core invariants (no render-path allocation, byte-identical replay, log-then-apply) held on every traced path. Five majors and several minors fixed before ship.
> **Disposition:** (major 1) meters were write-only through the plugin path → the mixer now provides `Arc<MeterBank>` under the `mixer.meters` context key (`ctx.get::<Arc<MeterBank>>`), with a test through `Engine::mount`; (major 2) `MAX_AUDIO_INS` was unenforced (a 9th input silently summed into nothing) → `add_node` now asserts the cap, plus a `#[should_panic]` test; (major 3) `set_param` rejected scheduled-but-not-yet-applied mounts, inconsistent with `patch` → validation now accepts scheduled-or-mounted, tested; (major 4) unknown param names were logged and silently no-op'd, eroding "refusals never logged" → the `Plugin` trait gained a declared `params()` surface (`ParamDef { name, min, max }`), registered in `register_factory`, and `Engine::set_param` refuses undeclared/non-finite/out-of-range names before logging; (major 5) the `(plugin, param)` `&'static str` namespace cannot address per-clip entities → recorded as a decision for the P1.3 clip-editor step (string interning or a target-id on `SetParam`) before it builds on the seam; (minor 6) `remove_node`'s cord index-shifting was untested → added a middle-node-removal test (with the blip-tail nuance); (minor 7) SetParam validated against a mount destroyed by a same-frame unmount → documented (replay-safe, apply-time skip); (minor 8) stale module doc + unenforced single-audio-Out → docs updated, `add_node` asserts ≤ 1 audio Out; (minor 9) the first-node-wins fallback re-opened the A.5 bus hole after a mixer unmount → the fallback now requires an audio Out port (a trigger-only first node can't become the bus); (minor 10) meter tap points + mute-vs-solo undocumented/untested → channels meter post-gain/pre-mute, mute is absolute (wins over solo), both tested; (nits) `Graph::set_param` doc'd as unlogged, NaN/range validation added, `MeterBank::channel_peak`/`master_peak` accessors, `MIXER_CHANNELS`-into-logs noted as a log-format decision. **Major findings (kimi's own words, condensed):**

1. **Meters are write-only through the real plugin path** — `MixerPlugin::apply` constructs `MixerNode::new()` inline and boxes it; the `Arc<MeterBank>` lives only inside the node; `AudioNode` has no downcast, `Engine::node_of` is private. In the mounted, logged configuration the meter atomics are written every block and unreadable by anyone. Fix: keep a clone on the plugin side and expose it (ctx service), then test through `Engine::mount`.

2. **`MAX_AUDIO_INS` is documented but unenforced** — `add_node` allocates one scratch buffer per declared port with no cap; a 9-port node's 9th input receives summed audio that is then dropped. Exactly the silent divergence the engine's fail-loud discipline exists to prevent. Fix: reject or clamp at `add_node`; add a test.

3. **`Engine::set_param` rejects scheduled-but-not-yet-applied plugins, inconsistent with `patch`** — the natural "mount, patch, set initial gains, then render" pattern works for mount/patch at frame 0 but is refused for `set_param`. Fix: accept `scheduled` too; the scheduler's same-frame FIFO guarantees the mount applies first.

4. **Unknown/misspelled param names are logged, replayed, and silently no-op'd** — the name goes into the permanent log unchecked; the mixer handles bad names with `debug_assert!(false)`, so in release a typo is a dead log entry that does nothing, forever. "Refusals never logged" becomes vacuous. Fix: validate the name against a declared surface before logging.

5. **The `(plugin, param)` `&'static str` namespace cannot address the clip-editor's entities** — "clip 17's gain", "region 3's fade" have no `&'static str`, and there is no target-id field. Fix before P1.3 designs against it: intern strings or add an entity/target id to `SetParam`.

**Minor findings:** 6. `remove_node`'s cord index-shifting never exercised (middle-node removal test needed). 7. SetParam validated against a mount destroyed by an earlier same-frame unmount (document; make the release path non-silent or accept the replay-safe skip). 8. Stale module doc + unenforced single-audio-Out asymmetry. 9. After the mixer unmounts, the first-node-wins fallback quietly re-opens the A.5 hole. 10. Meter tap points and mute-wins-over-solo undocumented and untested.

**Nits:** `Graph::set_param` remains an unlogged escape hatch (doc it); no NaN/value sanitization; `MeterBank::peak(MIXER_CHANNELS)` magic index; temp-file cleanup on failure; `MIXER_CHANNELS = 4` baked into logs is a log-format decision.

**What kimi found sound:** same-frame ordering + block-split apply path (true sample-accurate SetParam, proven at the exact boundary frame); per-port fan-in mechanics for the shapes that exist (scratch indices, `remove_node` lockstep, port-index stability, deterministic summation order); the mixer math that is tested (gain-weighted sum, mute, any-solo rule, master fader to 1e-6); no render-path allocation; the log discipline on happy paths; bus ownership in steady state.
