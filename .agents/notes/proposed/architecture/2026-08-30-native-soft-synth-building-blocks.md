# Agent Note: Native soft-synth building blocks — own modules on fundsp/dasp, own graph

Status: proposed

## Problem

The platform wants to design **our own soft-synth voices in Rust**: import an oscillator (VCO), a filter, an ADSR envelope, an LFO and compose them into an instrument that mounts in the patch bay like any other provider (the `tone` plugin is a fixed blip — an audible generator, not a configurable synth). Research (§10, [softsynth-integration-routes](../../../../research/architecture/2026-08-19-softsynth-integration-routes.md)) already answers *how third-party synths arrive*: CLAP via `clack` (Route A, zero per-app work), SuperCollider as an external server via the `OscSink` seam + JACK (Route B), Csound as an embedded C library or the sculptor's `OfflineProcess` sidecar (Route C). It does not answer *how we implement our own instrument*: which Rust DSP library supplies the blocks, and whether it becomes our patch graph or stays behind it. That is the gap this note closes. The direction was validated 2026-08-30 by a feature-gated spike in `crates/engine` (`plugins::fundsp_synth`) — see [`## Spike validation (2026-08-30)`](#spike-validation-2026-08-30).

## Proposal

**Keep our own `AudioNode`/patch-bay graph as the abstraction; use fundsp (and dasp) as the tested per-sample DSP *algorithm* source and wrap its blocks into our own module set.** Do not adopt fundsp's type-level graph notation or glicol's DSL as the patch model.

- **Our graph stays the graph.** The patch bay is a first-class, loggable, diffable *value* (nodes/edges/params) that the interpreter renders allocation-free and the log replays byte-identically (Phase-0 invariant). A synth's *patch* must be able to be this kind of value, which rules out swallowing fundsp's graph or glicol's engine.
- **fundsp/dasp are the block *library*, not the graph.** Their documented strengths are per-sample components — oscillators, `butterpass`/`lowpole`/`resonator` filters, delay/reverb, `envelope`/`lfo`, sample/frame types, `no_std`. We wrap individual components (or thin composites) as our own blocks behind `AudioNode`, so their *existence and params* are values in our graph (the opaque tier) while their *code* is trusted in-process.
- **The opaque tier is the home.** A synth voice mounts as `NodeKind::Opaque(Box<dyn AudioNode>)` exactly as `ToneGen` does today; it declares ports (`note`/`audio`, plus `control` for params), reports `latency()` for PDC, and consumes our `Note`/`Trigger`/`Control` streams in-block (sample-accurate, not wall-clock). The mixer keeps owning the master bus.
- **Two-block-tier reconciliation.** fundsp has a static `AudioNode` (monomorphized, stack, compile-time arity) and a dynamic `AudioUnit` (`Box<dyn AudioUnit>`, runtime arity, with a `Net` + `backend()`/`commit()` for real-time-safe topology swap). For a configurable, patchable voice the dynamic `AudioUnit`/`Net` is the natural fit; the static form is available for hot per-voice paths. `allocate()` is called before the RT thread; topology changes go through the frontend/`commit()`, matching our atomic-swap discipline.
- **We build the layer above the blocks, not the DSP math.** The distinct value: note→voice polyphony and voice stealing, envelope/param automation binding fundsp blocks to our control streams, the `Plugin`/`AudioNode` adapter that publishes a synth as a patch-bay provider, and the param surface (logged `SetParam`) for its inputs.

**External synths stay external.** SC = external server over the `OscSink` seam (notes → `/s_new`) + JACK; Csound = embedded `libcsound` behind an opaque node (realtime) or the `OfflineProcess` sidecar (offline); every third-party instrument = a CLAP plugin mounted as an opaque node via `clack`, state stored in the composition. OSC remains the *interop* protocol to them (and the SuperDirt-compatible `OscSource` endpoint receives Tidal), never the in-process path to our own voices — an instrument is called directly, not through an OSC hop.

## Spike validation (2026-08-30)

`crates/engine/src/plugins/fundsp_synth.rs` (gated on the optional `fundsp` feature) mounts a monophonic fundsp voice as an opaque `AudioNode`: a `Box<dyn AudioUnit>` for a `sine() >> lowpass_hz(cutoff, q)` graph, built and `allocate()`d at mount, with our own linear-decay envelope + gain and note scheduling from `io.notes_in` at sample offsets. `crates/engine/tests/fundsp_synth.rs` (7 tests) prove the claim: the voice sounds and its pitch follows the scale; a note onset is sample-accurate; rendering is byte-identical across replay; `set_param` is logged and undeclared params are refused; the render path allocates nothing (counting allocator); and `latency() == 0` (a minimum-phase biquad adds no whole-sample delay, so PDC composes correctly). The dependency is optional and feature-gated so the minimal core stays dep-lean by default (`cargo test -p engine` builds without fundsp). All 8 tests pass in **both debug and release** — validating the spike in release surfaced a pre-existing core bug (scheduled mounts never applied in release, so the engine was silent on every mounted path), now fixed ([bug-fix note](../../implemented/bug-fix/2026-08-30-scheduled-mounts-apply-in-release.md)).

## Alternatives considered

- **Adopt fundsp's graph notation as our patch model** — fundsp's combinators *consume* their arguments and enforce an acyclic tree, and the graph is baked into Rust types/closures, so it is compile-time, not serializable data, and it has **no note/trigger/event type** (notes are expressed as control signals via `Sequencer`/`midi_fundsp`). That collides with our patch-as-value + sample-accurate note/trigger streams. Rejected; use fundsp's components, not its graph.
- **Adopt glicol as the synth engine (DSL)** — a graph-oriented live-coding language + audio engine (Rust → Wasm/AudioWorklet, Bela, VST), but self-described "highly experimental, API may change before 1.0.0", last release ~2024-04, and the published crate's license is reported "non-standard" (repo file is MIT). Adopting it means adopting its DSL, AST and graph-update model, which is not our patch value. Rejected for release; keep as an algorithm/design reference.
- **Build our own DSP primitives from scratch (no external DSP crate)** — reinvents maintained, permissive, well-tested oscillators/filters/envelopes. Rejected; the cost is in the voice/patch layer, not in re-deriving a biquad.
- **Make SuperCollider/Csound the native instrument mechanism** — they are an external synthesis *server* over OSC (GPL) and a hosted *C library* (LGPL) with instruments written in their own language, not composed Rust blocks. Rejected for our own voices; they remain hosted/embedded external targets (Routes A/B/C).
- **Depend on `augmented-audio` for the blocks** — `augmented-oscillator` (1.4.0) and `augmented-dsp-filters` (2.5.0) are MIT library crates, but the repo is literally labeled "draft/experiments", last releases are ~2024 (dormant), there is no published `augmented-adsr`/`augmented-music-theory`, and the full *apps* are AGPLv3. Rejected for release; keep as an algorithm reference (use only the MIT lib crates if ever adopted).
- **Host/export our synths via `nih-plug`** — the framework is in maintenance mode, the crate no longer resolves on crates.io/docs.rs, and its VST3 bindings (`vst3-sys`) are GPLv3, so VST3 output is GPL-encumbered. Rejected as the export path; use **`clack`** (permissive, `clack-host` 0.1.1, actively maintained) if/when we need plugin host or export.

## Acceptance criteria

- A single note records the decision with its rejected alternatives (this note) and RESEARCH §10 links to it rather than restating it.
- RESEARCH §10 reflects the current verified state (versions/dates/dormancy) so the "use fundsp, avoid glicol/augmented-audio/nih-plug for release" reasoning is visible in one place.
- A future spike (not this change) can wrap one fundsp `AudioUnit` voice as an opaque `AudioNode` behind a `tone`-style plugin and satisfy: zero allocations steady-state render, byte-identical replay, `set_param` logged, correct `latency()`/PDC.

## Risks

- **Real-time safety of the DSP layer** — a wrapped fundsp `AudioUnit` is *constructed* on the control side and `allocate()`d before the audio thread; topology changes go through `Net::commit()`. Must still pass the counting-allocator and no-block checks (our opaque-node contract).
- **Sample-rate / timing** — call `set_sample_rate` explicitly and drive from our in-block `Note` events, never wall-clock.
- **Dormant dependencies** — fundsp is active (0.23.0, 2026-01) but an algorithm reference we copy from is a different maintenance risk than a dependency; keep the dependency surface small and permissive (MIT/Apache-2.0, fine under GPL-3.0-or-later).
- **Graph-as-code vs graph-as-data** — the sharpest structural risk: a patch built from wrapped blocks must still expose a loggable, diffable param/port surface (the opaque tier's "existence + params are values, code is trusted" rule), not a non-serializable closure. This is why the blocks stay *behind* our graph, not *become* it.
- **DSP dependency in the minimal core** — fundsp pulls ~12 crates even with `default-features = false`; the feature-gate keeps it lean by default, but a reviewer would object to a DSP dependency in the "minimal, model-free" core long-term. Next step: extract the voice into a separate `crates/fundsp-synth` that depends on `engine`, once the polyphonic voice pool is built. This spike is the bridge, not the end state.
- **Click-free retrigger + cutoff automation** — the spike hard-resets the fundsp filter on every onset (back-to-back notes click) and bakes `cutoff`/`q` at mount (no cutoff automation). Both are voice-layer gaps for a real soft synth; the next step (preallocated polyphonic voice pool with deterministic stealing + crossfade + runtime-cutoff control) is above the blocks, not this spike. It also ignores `NoteEvent.duration`/`velocity` — fine for a blip-era POC.
