# Agent Note: P1.3.3 — the media pool (enumeration + crash recovery)

Status: implemented

## Problem

The pool is a directory of immutable float-WAV sources + `.peaks` sidecars,
take-id-addressed (`{take_id}.ch{N}.wav`). Before this slice there was no way to *enumerate*
it (a timeline UI cannot read it), and no recovery for a crashed take — the recorder writes a
placeholder header first and patches it on finalize, but a crash leaves a non-finalized file
(missing/missized header) and no peaks. The value a host needs (sources, frame counts, peaks)
did not exist.

## Decision

`crates/media/src/pool.rs` adds:

- **`Pool::list() -> PoolIndex`** — enumerate `.wav`s (sorted for a deterministic index), each
  with its frames, sample rate, channel count, `.peaks` presence, and `finalized` flag. **No `PoolDir`-size
  does.** A source that cannot be read is reported in `errors` and skipped — a crash day is
  when a broken file is likely, so one bad source must not blank the whole index.
- **`Pool::recover() -> Recovery`** — **finalize** un-finalized takes
  (`WavWriter::recover` — patches the frame-aligned size, truncates a torn tail) and **rebuild
  missing *or corrupt* `.peaks`** sidecars (validated by `PeakFile::read`, not `is_file`).
  Per-source failures are reported, never fatal to the rest. **Ordering is load-bearing:**
  a take is finalized *before* its peaks are rebuilt, so the peak frame count matches.
- **`Pool::path_for(id)`** — resolves a source stem to its `.wav` path, **rejecting a
  non-plain stem** (a clip id is user-craftable and must not escape the pool directory),
  and **`Pool::resolver()`** returns that lookup as a `PoolResolver` — **the way a host
  builds the resolver it hands the arranger**, because a resolver that joins the id onto
  the directory itself turns `../escape` into a file outside the pool. That was the
  defect: this guard existed and nothing on the production path called it, because
  `valid_id` was private and a host could not have applied it. See the [clip-source
  fix](../bug-fix/2026-09-29-a-clip-source-is-a-pool-id-not-a-path.md).
  Since 2026-09-24 the rule is **strict about whitespace** as well: a pool id is also a clip
  source id and the space-separated `host v1` log must be able to name it back, so an id with a
  space could exist on disk but never be addressed — including by the offline render seam,
  whose doc had promised the whitespace-free rule while `valid_id` allowed one (found by the
  E2b gate). `Pool::import` therefore **sanitizes** the stem it derives from a filename
  (`My Take.wav` → `My_Take`, whitespace → `_`) and reports the real id through `Import::id`,
  so a space in a filename is still importable, while a path separator or a `.`/`..` stem is
  still refused (a mangled path would be a surprise; a mangled space is not).
- **`WavWriter::is_finalized(path)`** — whether the file holds at least every frame it declares,
  `data_offset + declared_data_bytes <= file_len`. A crashed take declares more than the file holds
  (the placeholder size) and reports `false`. A file holding *more* than it declares — a trailing
  `LIST`/`INFO` chunk, the RIFF pad byte after odd-length 24-bit data — is legal and reports `true`,
  and `WavWriter::recover` refuses it outright ([recovery salvage
  note](../bug-fix/2026-09-29-recovery-salvages-only-what-is-there.md)); that refusal is what makes
  the "never mutates a well-formed source" invariant below hold for foreign WAVs and not only for
  files this crate wrote.
- **`PeakFile::write` is now atomic** (write `${path}.tmp` then rename, so "exists ⇒ valid")
  and **`PeakFile::read` bounds its allocation** (a level length exceeding `frames/base_bin`
  fails loud rather than allocating gigabytes from a corrupt sidecar).

**A pool source is mono** (`channels == 1`) and at the session rate: capture writes one file per
channel (`{take_id}.ch{k}`), `Pool::import` splits a multi-channel file the same way, and
`Pool::conform` expands a legacy multi-channel source in place. `PoolSource.channels` reports what the
file actually holds, so a source that is not yet mono is visible rather than silently played as its
channel 0 ([stereo-material
note](../../../../.agents/notes/implemented/feature/2026-09-24-stereo-material-per-channel-pool.md)).

Sources are immutable *post-finalize*; recovery only finalizes crashed takes and *derives*
sidecars — it never mutates a well-formed source.

## Alternatives considered

- **One bad `.wav` aborts the whole `list()`** — the first draft; rejected after the kimi
  pool review: the morning after a crash is exactly when a broken file is present, and
  recovery (which `list()` feeds) never ran. Per-source error isolation is the fix.
- **Rebuild `.peaks` only when `!is_file()`** — rejected (kimi must-fix 2): a truncated
  sidecar *exists* but is unusable, so it was never rebuilt. Now validated by `read`.
- **Trust the `.peaks` length prefix unchecked** — rejected (kimi must-fix): a corrupt
  sidecar could claim billions of bins. Bounded.
- **Leave `list`'s frames as-is without a `finalized` flag** — rejected (kimi should-fix): the
  UI couldn't tell a healthy take from a crashed-pending-recover one.

## Consequences

- A host can now enumerate the pool (the timeline UI's data source) and recover a crashed
  session non-destructively. Recovery is deterministic (sorted, per-source isolation).
- 4 pool tests: list sources/frames/peaks-status, finalize-a-crashed-take (flush+forget
  simulates the crash), rebuild-missing-peaks, path_for. 16 workspace suites green, clippy
  clean. (Later slices added the import/conform/split tests; see the notes above.)
- **Deferred**: u32 data-size ceiling (a single float-WAV > 4 GiB of audio needs RF64 — a take whose
  declared size saturates the field can no longer be told from a file that holds more than it
  declares); `WavReader::read_into` swallowing I/O errors
  (a mid-stream read error reads as EOF — the pool's peak-frames cross-check via
  `PeakFile::read` now catches a resulting mismatch); the host wiring of the pool to the
  timeline UI (P1.3.4).
