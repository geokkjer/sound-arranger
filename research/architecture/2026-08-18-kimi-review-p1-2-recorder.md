# Second opinion — kimi-cli review of P1.2 (recorder path + adaptable mixer)

> **Source:** `kimi-cli` non-interactive review, 2026-08-18 (kimi session `session_50bf31dc-1fc4-466a-953f-568405ed48e6`).
> **Reviewed:** the [P1.2 note](../.agents/notes/implemented/architecture/2026-08-18-p1-2-recorder-and-adaptable-mixer.md), the adaptable mixer (`channels` mount param), the float-WAV pool writer, the live peak pyramid, the multi-channel capture (demux + CaptureNode), the device config accessor, and the P1.2 acceptance tests.
> **Disposition:** (major 1) source-ring overruns in the cpal callback were silently dropped → `InputHandle` now carries a shared overrun counter, incremented per failed push; (major 2) peak level indexing was off by one between `levels()` and the sidecar → `levels()` now includes the base as level 0, with a levels-vs-sidecar consistency test; (major 3) the note claimed a per-channel `RecorderPlugin` that can't exist under one-node-per-plugin → the note now states shipped reality (graph-level `CaptureNode`s, Spike-B pattern), records the log-visibility carve-out, and moves the plugin design to Alternatives with the rejection reason; (major 4) the e2e underrun assertion was timing-dependent → demoted to a diagnostic (glitch-freedom is proven by the *exact* master content, which a dropped sample would shift); (major 5) two acceptance criteria were untested → added a pool-peaks-vs-independent-reduction test and a counting-allocator test over a capture→mixer graph; (minor) trailing partial frame at stop counted, panicked demux propagates the join error, failed writers are taken out of the loop, `recover` patches a frame-aligned size, 32-bit-PCM-misread-as-float rejected in the header parser, pool writers open synchronously in `Capture::start` (fail-loud), fractional `channels` refused, `take_id` validated for filenames, out-of-range channels return `Err` not panic, sidecar read caps allocation; (nit) beyond-mount patches + boundaries tested. **Kimi's findings (condensed):**

**Major:** 1. Source-ring overruns silently dropped in the cpal callback (`devices.rs:142` `let _ = ring.try_push(...)`) — the one drop that corrupts the authoritative pool artifact is uncounted. 2. Peak level off-by-one: `levels()[0]` was the ×2 reduction while sidecar level 0 is the base — mixed consumers draw the wrong zoom. 3. The note specified a `RecorderPlugin` that doesn't exist; tests wire `CaptureNode`s via direct graph calls, bypassing `Engine::patch` — the monitoring topology is invisible to the session log ("rendering is a pure function of the log" gains an undocumented carve-out), and nothing prevents a live CaptureNode in a bounced graph. 4. The e2e zero-underrun assertion is timing-dependent (flake risk). 5. Two acceptance criteria untested: no counting-allocator test over a capture→mixer graph; pool peaks never checked against an independent reduction.

**Minor:** trailing partial frame at stop dropped uncounted; panicked demux reports success; failed writers stay in the write loop; `recover` patches a possibly non-frame-aligned size; 32-bit PCM accepted then decoded as float; writer-open failures deferred past `start()` (silent empty take on an unwritable pool); fractional `channels` silently truncated; `take_id` unvalidated in filenames; library panics where it returns `Result` (>8-channel devices panic the hardware test); sidecar read trusts counts into allocation.

**What kimi found sound:** the demux core (whole-frame batching with partial-frame preservation, drain-before-break, per-sample monitoring drop counting); the SPSC ring protocol and both audio-path consumers; the adaptable mixer (factory validation, logged `channels` replayable — byte-identical replay tested, deterministic ignore-beyond-mount, documented meters, no render allocation); the float WAV writer (correct header, placeholder+patch crash design, reader clamps to file length, bit-identical float round-trip tested); the peak base-bin math, partial-bin finalize, monotone upper levels, sidecar round-trip; the off-render-path allocation discipline.

**Recorded for P1.3 (the clip editor):** the pool needs a real abstraction (enumeration, `seek_frames` reads, `PeakFile::read`, the crash-recovery pass — `recover` un-finalized WAVs and rebuild their peaks on pool open); the log-visibility carve-out for graph-level media nodes must be decided (exclude CaptureNode from bounce or log its presence); `Capture` should become a ctx-shaped service like `mixer.meters`.
