# Second opinion — kimi-cli review of the Host API + headless reference host

> **Source:** `kimi-cli` non-interactive review, 2026-08-18 (kimi session `session_d72cbbf1-a0d7-4eb2-b62d-1adbc9e8065f`).
> **Reviewed:** the [UI-as-plugin note](../../.agents/notes/implemented/architecture/2026-08-18-ui-as-plugin-host-api-and-headless-reference.md), `crates/host` (the `HostCommand` contract, `HostSession`/`run_script`, the versioned text parser), the CLI smoke binary, and the reference-host tests.
> **Disposition:** (critical 1) determinism rested on an unwarmed player ring (a thread race) → the host now warms each player's ring synchronously at apply (bounded poll), so byte-identity is a mechanism, not luck; (critical 2) commands had no temporal placement (everything applied at frame 0 — "the gain change at 7000" was fiction) → every engine command and `Play` now carry `at_frame: Option<u64>`, `run_script` renders up to each command's frame first, and the log records real frames (tested: the SetParam logs `at_frame: 2000`); (major) panics in the contract path → `Play` validates the mixer is mounted + the channel is within its count at apply, wiring returns `Err`, the mailbox lock is mapped; `channel_of` bound-checks ch0..ch7 (tested); the discarded-first-block in `render()` → the engine gained `flush_scheduled()` (apply due events without rendering) and the host wires cords after it, so no audio is dropped; the contract is now **versioned** (`HOST_API_VERSION`, `host vN` first line, mismatches refused) and the registry is split per slot (plugins/ports/params); media commands are reported separately (the log covers engine commands; the host reports both — `media_command_count`); `Record` is declared but device-gated with a clear error; the canonical test now splices at 4000 *inside* the bounce window, asserts `deferred == 0` and that the spliced bounce differs from an unspliced control; logs are compared by content, not length; `unmount`/`set_tempo` are now fail-loud engine-side (unknown plugin / non-positive tempo refused, never logged); unmount/set_tempo/play-twice/splice-without-play are executed and refused in tests; the smoke-binary test covers stdin, determinism through the binary, and the bad-script exit code. Full text preserved below.

**Kimi's findings (condensed):**

**Critical:** 1. Byte-identical bounce rests on a thread race — the host issues `Play` then `Bounce` renders immediately with no warm-up; the first render blocks can pop an empty ring (zeros → flaky determinism). 2. `HostCommand` has no temporal placement — every command applies at frame 0, so "the log is the command list" is degenerate (it records *what*, never *when*).

**Major:** 3. Panics in the contract path (`expect` on out_node/connect, `lock().unwrap()`) violate fail-loud. 4. `channel_of` accepts `ch9`+ (its error message lies; the test gave false confidence via HOST_NAMES). 5. `render()` discards a block to force scheduled mounts — every session with `Play` bounces starting at frame 512, and a mid-session `Play` punches a hole. 6. The contract is unversioned and unserializable — acceptance criterion 3 unmet. 7. `&'static str` throughout makes the contract unconstructible by a real shell (IPC delivers owned strings). 8. `HOST_NAMES` hand-duplicates factory metadata, flat/unscoped, and static while the mixer channel count is dynamic. 9. The Play/Splice carve-out quietly breaks "the log is the command list" (a session with clips has a log indistinguishable from one without); no Stop. 10. Fail-loud is asymmetric: `unmount` logs unconditionally (unknown plugin) and `set_tempo` validates nothing. 11. The events/values two-thirds of the contract don't exist but the docs claim them; `RecordStart`/`RecordStop` declared in the note but absent. 12. The canonical determinism test never actually splices (splice at 60000, render 10512). 13. "Logs identically" asserted by length only; `Unmount`/`SetTempo` never run; refusals untested.

**Minor/nits:** smoke binary stdin/exit-code/determinism untested; text-format sharp edges (comment stripping vs paths with `#`, error line numbers, "bad frame(s)"); `HostSession::engine()` re-opens the boundary the note rejected egui for; `summarize` prints internal NodeId Debug; note status/accuracy.

**What kimi found sound:** the two-mode split (engine plugins in-process, host plugins through the contract) and its rationale; headless-first ordering; the refusal model (validate at apply, refuse before the log, refuse identically on replay); the media seam the host builds on (control-side allocation, pop-only render, detached readers); the `ClipRef` resolution split (parser does no file I/O, lengths resolve at apply); the minimal honest binary; the tests being real end-to-end tests (actual WAVs, actual spawned binary, actual bytes).
